# ADR-0001: Evidence-bound, cross-harness durable shadow decisions

Date: 2026-09-18. Status: implemented alpha slice; not a production readiness claim.

## Decision

ReflexMesh will be a semantic decision runtime attached to existing agent boundaries, not a new agent framework, authorization product, memory database, or Jev-only MCP wrapper.

The distinctive engineering object is the **bound decision record**: one versioned question/policy contract, one deployment binding, one admitted event/action, and separately attributable outcomes/labels. The point is preserving those relationships across restarts and heterogeneous harnesses, rather than inventing another classifier endpoint. This is a design differentiation, **not a first-ever or patent-novelty claim**.

The implementation in this change keeps the existing policy and execution engine and adds a durable wrapper. It intentionally does not implement every idea from the research roadmap.

## Research conclusions translated into code

| Conclusion | Implemented now | Deliberately deferred |
| --- | --- | --- |
| MCP alone is not enforcement | Codex advisory channel is explicitly named; Claude/DSH observe their real lifecycle seams without granting permission | Credential-isolated execution proxy and reviewed enforcement mode |
| Contracts should survive provider changes without pretending scores are interchangeable | Immutable pack digest; explicit provider/model/revision and host revisions; different binding cannot silently reuse an event | Capability negotiation, real second classifier provider, labeled migration gates |
| Crash recovery is part of decision semantics | SQLite transaction admission, epochs, recovery-required tombstones; pre-call vs executing crash distinction | Operator reconciliation, outbox, lease renewal, distributed storage |
| Outcome is not truth | Separate observations/labels; model-reported MCP results never become test labels | Dataset import, label review UI, calibration fitting |
| Replay must not rerun actions | Pure policy-only replay over stored predictions with matching question digest | Paired new-provider inference under separately budgeted shadow deployment |
| Avoid giant frameworks early | One package, existing v0.1 engine reused; generic portable pack facade | Monorepo split, visual graph editor, workflow engine |

## Prior-art boundaries

JevWire already targets Jev integration and agent judgment tooling; DeepSeek Harness is itself a plugin-based agent runtime; policy/authorization systems and observability stores already serve their own layers. ReflexMesh should compose with these layers. It must not claim their single-point capabilities as novel merely because they are packaged together.

The testable hypothesis is narrower: **a shared contract and durable evidence protocol can reduce integration-specific semantic drift and unsafe recovery without taking over the agent loop**. This alpha demonstrates transport fixtures and failure invariants. It does not yet prove latency savings, improved model accuracy, competitive superiority, or real-host compatibility.

## Accepted compromises

- A generic `binary/choice/ordinal` authoring facade compiles to the existing v0.1 contract. This is an incremental migration, not a claim that Jev-specific terminology has vanished from the engine.
- Synchronous SQLite simplifies atomic admission but is for bounded local workloads, not a high-throughput multi-tenant service.
- Unknown actions remain blocked for manual investigation. Less availability is preferable to silently replaying possibly completed work.
- Shadow transport entrypoints default to genuine abstention with no provider configured. Synthetic predictions are limited to explicit tests/demos.
- An outcome digest proves linkage only within this application's trusted storage; it is not remote attestation or truth validation.

## Evaluation gates

Keep the original 45 regression tests. Add independent-connection and separate-process races; real SIGKILL tests before/after action start; exact argument/outcome matching; same-key different-contract conflicts; source-matched harness fixtures; pure replay; missing-provider and malformed-input paths.

Before an enforcement release: run each actual pinned host, measure overhead and lost-event rates, verify egress minimization and credential isolation, add manual recovery/retention, and evaluate false-allow/false-deny on independently labeled data. No success-from-absence-of-incidents label is acceptable.
